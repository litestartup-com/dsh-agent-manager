# ADR-0001 · 回合驱动语义（订阅先于发送 / 只计 live 帧 / 逐响应计价 / 会话归还）

- 状态：已接受（2026-09-12 由长论证注释固化；行为自 0.1.1 起未变）
- 相关代码：`src/runner.ts`、`src/runner/turn.ts`、`src/gateway/stream.ts`

## 背景

一个 agent 回合的驱动方式决定「什么被计费、什么被转发、会话名额何时归还」。
早期实现把这些论证写在 `runAgent` 模块注释里（35+ 行设计随笔），与代码同寿命、
随重构漂移。E1 拆分 runner 后，结论固化至此，源码只留一行引用。

## 决策

1. **订阅先于发送**：stream 必须在 `prompt`/`sendMessage` 之前订阅。gateway 的
   `hello` 帧会回放整个持久化历史——晚订阅者无法区分「回放」与「直播」，
   而只有直播帧代表本回合的真实消耗。
2. **只计 live 帧**：usage 只从直播 `message` 帧累计。若把 `hello` 历史计入，
   每个续接回合都会把此前所有回合再计一次费，且随会话长度线性增长。
3. **逐响应计价**：每个响应到达时按其时刻计价，而不是回合结束时一次计价。
   DeepSeek 按分时计价（峰/谷两档），长回合可能跨峰谷边界——单个结束时刻
   会把整个回合记在钟表错误的一侧。
4. **会话归还（release 而非 delete）**：一次性回合（cron/手动/抓取）默认归还
   gateway 会话名额；会话保留（keepSession）是对话回合的显式要求。gateway 的
   `maxSessions` 是硬上限——不归还的一次性回合最终会把所有对话堵死。release
   不删除 transcript：会话仍可读、可被 adopt 回去。
5. **静默超时 ≠ 总超时**：总超时必须宽松（20 分钟的正常回合合法）；静默超时
   是兜底——工作回合持续发帧（delta/tool call），长时间零帧意味着「停住」而
   非「慢」，典型是等一个无人能答的交互式提问。两者独立，谁也不替代谁；
   静默兜底在有人等待回答（awaitingHuman > 0）时停摆，总超时仍兜住全局。

## 后果

- 计费正确性依赖「hello 与 live 的区分」，任何帧通路改动（E8 zod 判别、
  E1 帧处理器）都必须保住 `runner` 33 用例与 `chat` 16 用例里的
  「replayed history is never billed again / only live frames are relayed」。
- 会话归还路径的失败只告警不吞回合结果（回合已跑、钱已花，结果不能因清理
  失败而丢）。
